# 性能基准测试

## 测试方法

- 每个场景测试 5 次，取平均
- 记录预测置信度和整体置信度
- 样本覆盖中文和英文

## 准确率排行榜

### 第一梯队（置信度 > 90%）

| 场景 | 文本示例 | 预测结果 | 置信度 |
|-----|---------|---------|-------|

| 语法错误 | "syntax error near unexpected token" | syntax | 99.4% |

| 正面评价 | "产品体验很好，谢谢" | positive | 96.4% |

### 第三梯队（置信度 50-70%）

## 典型失败模式

### 1. 标签语义重叠
```
文本: "你们的售后服务怎么样"
预期: inquiry
实际: return (84.9%)
原因: 训练数据中"售后"与"退货"关联较强
```

### 2. 描述过于模糊
```
文本: "代码报错"
预期: 明确分类
实际: runtime/logic/syntax 各 ~20%
原因: 缺乏错误细节
```

### 3. 上下文缺失
```
文本: "退款能快点吗"
预期: negative (不满)
实际: neutral (89.6%)
原因: 中性语气表达催促
```

## 改进建议

1. **自定义标签** — 根据业务调整选项，避免重叠
2. **增加上下文** — 提供用户历史、订单状态等辅助信息
3. **低置信度过滤** — 置信度 < 0.6 时走人工或 LLM
4. **A/B 测试** — 不同标签组合对比效果
